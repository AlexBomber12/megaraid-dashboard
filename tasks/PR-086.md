# PR-086: HTMX 30s polling integration for live updates

Branch: pr-086-htmx-polling-integration
- Type: feature
- Complexity: medium
- Depends on: PR-085
- Priority: 2
- Coder: any

## Problem

The new dashboard layout shows a green dot + "Auto-refresh 30s" indicator in the header (PR-081). This indicator is currently decorative. Per the design decision (HTMX partial updates over SSE), every 30 seconds the browser should silently refresh the controller summary card and drive grid, so the operator sees fresh data without manual reload.

## Scope

In scope:

1. New endpoint `GET /partials/main-page` in `web/routes.py`:
   - Returns the HTML partial for the main page's controller card + drive grid + activity timeline.
   - Auth required.
   - Cache-Control: `no-cache` (always fresh).
   - Returns the same rendered partial as the section of `pages/main.html` that should refresh - a separate template `partials/main_page_refresh.html`.

2. Update `templates/pages/main.html` to wrap the refreshable content in an HTMX-aware container:
   - `<main hx-get="{{ url_for('main_page_refresh') }}" hx-trigger="every 30s" hx-swap="innerHTML">` around the content that should refresh.

3. Create `templates/partials/main_page_refresh.html` that renders just the inner content (controller card + drive grid + activity timeline), without page chrome.

4. Update the refresh indicator in `partials/site_header.html` to pulse (CSS animation) when HTMX polling is active.

5. Document the polling behavior in `docs/ARCHITECTURE.md` (or create one if absent).

Out of scope:
- Polling on controller detail page (consider for later).
- Polling on drive detail page (consider for later).
- SSE / WebSocket (deferred per design decision).
- Pause-polling-when-tab-hidden optimization (could be future PR).

## Implementation notes

The HTMX endpoint reuses `load_main_page_view_model` from PR-075. The only difference is the rendered template: `pages/main.html` (full page) vs `partials/main_page_refresh.html` (just the swappable content).

To avoid duplication, the partial template can use `{% include "partials/controller_summary_card.html" %}`, `{% include "partials/drive_grid.html" %}`, `{% include "partials/activity_timeline_v2.html" %}` - the same partials that the full page uses.

HTMX polling overhead: every 30s, ~10-20 KB partial HTML is fetched. Over a 1-hour browser session, ~120 requests, ~1.5 MB total. Acceptable for homelab.

Browser tab visibility API: out of scope. The polling continues even when tab is in background. If this becomes an issue (battery drain on laptops), revisit with `document.visibilityState`.

## Risk

Adding HTMX polling to a route that already exists. Test that:

- Polling does not break browser refresh button.
- Initial page load shows correct data (not stale).
- Polling stops gracefully when user navigates away.
