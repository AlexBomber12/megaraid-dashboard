# PR-091: Fix controller card link to point at controller detail page

Branch: pr-091-fix-controller-card-link
- Type: bugfix
- Complexity: low
- Depends on: PR-090
- Priority: 2
- Coder: any

## Problem

On the main page, the controller summary card is a clickable link. It currently points at the legacy foreign-config page instead of the new controller detail page.

In `templates/partials/controller_summary_card.html`:

```
href="{{ request.url_for('controller_foreign_config').path }}"
```

The route for the controller detail page is named `controller_detail` (`@router.get("/controller", name="controller_detail")` in routes.py). The card should link there. As designed in the redesign mockups, clicking the controller card on the main page takes the operator to the full controller detail view.

This depends on PR-090 because the controller detail page returns 500 until PR-090 lands; linking to a 500 page would be worse than the current behaviour.

## Scope

In scope:

1. In `templates/partials/controller_summary_card.html`, change the card `href` from `request.url_for('controller_foreign_config').path` to `request.url_for('controller_detail').path`.

2. Update or add a test asserting the controller card links to `controller_detail`, not `controller_foreign_config`.

Out of scope:
- Any other link on the main page.
- Foreign config page itself (still reachable from the controller detail page's Destructive Operations section).
- Visual restyle.

## Files to modify

`src/megaraid_dashboard/templates/partials/controller_summary_card.html`:
- Change the single `href` to use `controller_detail`.

## Files to extend

`tests/test_web/test_main_page.py`:
- Add or update a test: the controller card anchor `href` resolves to the `/controller` path (the `controller_detail` route), not `/controller/foreign-config`.

## Files NOT to touch

- Routes (the `controller_detail` route already exists from PR-083).
- Other partials.
- View models.

## Implementation notes

One-line template change plus a test assertion. Verify the route name `controller_detail` is correct by checking routes.py (it is at the `@router.get("/controller", name="controller_detail")` decorator).

After this change, the operator flow is: main page controller card click goes to controller detail (which works after PR-090).

## Risk

Smoke test after merge: click controller card on main page, land on `/controller` with HTTP 200.
