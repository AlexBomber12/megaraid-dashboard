## Problem

PR-074a-d added the Playwright e2e test infrastructure with smoke + auth + CSRF + maintenance + locate + replace + static tests. The redesigned pages (main, controller detail, drive detail) need their own e2e coverage to verify the full user flow including HTMX polling, new POST forms (buzzer, advanced drive actions), and dynamic chart rendering.

## Scope

In scope:

1. New e2e tests in `tests/e2e/`:

   `test_main_page_redesign.py`:
   - Login + navigate to /.
   - Verify header has all 5 nav links.
   - Verify Overview nav is active.
   - Verify controller card visible with OPTIMAL state.
   - Verify drive grid has 8 tiles.
   - Click first drive tile -> lands on /drives/{e}:0.
   - Click controller card -> lands on /controller.
   - Verify status bar visible at bottom.
   - Wait 31 seconds and verify HTMX polling fetches partial (assertions on network mock or DOM change).

   `test_controller_detail_page.py`:
   - Navigate to /controller.
   - Verify all 8 sections rendered (Health, Operations, CacheVault, RoC chart, RAID, Scheduled, Hardware, Buzzer, Destructive).
   - Verify Hardware identity has 18 items.
   - Click "Silence" button in Buzzer Control -> form submits with CSRF, page reloads, audit event recorded.
   - Click "Disable" -> similar.
   - Click range tab "7d" in RoC chart -> chart re-renders with new data.

   `test_drive_detail_page.py`:
   - Navigate to /drives/252:0.
   - Verify breadcrumb shows Overview / Drives / Slot 0.
   - Click "Next" arrow -> lands on /drives/252:1.
   - Click "Prev" arrow -> back to /drives/252:0.
   - Verify error sparkline SVG present.
   - Verify backplane diagram shows 8 slots with S0 highlighted.
   - Verify temperature chart canvas fits within 280px height bound.
   - Click "Start Locate" -> form submits, audit event recorded.
   - Click "Mark as UBad" (if state allows) -> form submits, audit event recorded.
   - Click "Begin Replacement" -> navigation to replace wizard.

   `test_buzzer_control_flow.py`:
   - Click Silence button -> verify request POST to /controller/buzzer/silence with CSRF.
   - Verify audit log shows event with category controller_buzzer_silence.
   - Click Disable -> alarm state changes (mocked storcli response).

2. New helper functions in `tests/e2e/conftest.py`:
   - `wait_for_htmx_swap(page, timeout=35_000)` - waits for HTMX to complete a swap.
   - `assert_chart_height_within(page, selector, max_height_px)` - measures canvas height after render.
   - `login_and_navigate(page, path)` - convenience wrapper.

Out of scope:

## Implementation notes

The e2e tests run against the same live_server fixture from PR-074a (uvicorn in subprocess). The snapshot_with_drives fixture seeds DB with realistic data (1 controller + 8 drives).

For HTMX polling test: use `page.wait_for_response()` or `page.expect_request()` to detect the polling request. Verify the response is 200 with the partial HTML.

For chart height assertion: use `page.evaluate("(sel) => document.querySelector(sel).getBoundingClientRect().height", "#temperature-history-chart")` to read the actual rendered height. Assert it's <= 280.

For mocking storcli responses to buzzer commands: the existing storcli runner mock from PR-074a can be extended to recognize `set alarm=silence` etc. and return success.

These tests are slow (browser launch + page render). Run them in CI separately from unit tests. Skip locally when running quick pytest.

## Risk

E2E tests are inherently flaky. To minimize flakiness:
- Use explicit waits, no `time.sleep()`.
- Verify presence via Playwright locators with appropriate timeout.
- Run tests in headless mode with consistent viewport.
