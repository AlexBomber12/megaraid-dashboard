# PR-081: Frontend layout shell (header nav + page chrome)

Branch: pr-081-frontend-layout-shell
- Type: feature
- Complexity: low
- Depends on: PR-080
- Priority: 2
- Coder: any

## Problem

The frontend redesign introduces a new layout shell: header with nav (Overview/Controller/Drives/Events/Audit), auto-refresh indicator, clock; max-width 1320px content area; consistent dark theme. The existing layout `layouts/base.html` has a different shell pattern (sticky header with brand + maintenance banner + utc-clock) but lacks the nav. This PR replaces the shell.

This PR is shell-only. New page content lands in PR-082-085.

## Scope

In scope:

1. Update `templates/layouts/base.html`:
   - New header structure with brand link + horizontal nav + right-side meta (auto-refresh indicator + clock).
   - Content slot with `max-width: 1320px; margin: 0 auto; padding: 24px 32px;`.
   - Footer status bar slot (block that pages override).
   - Maintenance banner remains as conditional include.

2. Update `static/css/app.css`:
   - Header styles matching mockup (background, border, padding, sticky positioning).
   - Nav link styles (default, hover, active).
   - Auto-refresh indicator dot + label.
   - Content max-width container.
   - Status bar styles (bottom of pages, optional).

3. New partial `templates/partials/site_header.html` containing the header markup, included by base layout.

4. Active nav state: pages must set a `nav_active` block variable (e.g. `{% block nav_active %}overview{% endblock %}`) so the layout can mark the corresponding nav link as active.

5. Auto-refresh indicator: shows a green dot + "Auto-refresh 30s" text. The HTMX polling is wired in PR-086; this PR only renders the visual indicator.

Out of scope:
- HTMX polling logic (PR-086).
- New page content (PR-082-085).
- Removing legacy templates (PR-088).
- Light theme or theme toggle.
- Mobile responsive media queries (target is 1920x1080 per design decision).

## Implementation notes

The new header should NOT break any existing test that asserts on header content. Best strategy: keep existing `.site-header` styles working but introduce `.site-header-v2` as the new class. The page rendered by base.html uses v2 going forward; old tests that check v1 will fail and need updating - update them in this same PR.

The auto-refresh indicator is a visual element only here. It does not actually trigger refresh - that comes in PR-086. The indicator can show a static green dot. When PR-086 lands, the dot can blink to indicate active polling.

Nav active state: use Jinja's `{% if nav_active == "controller" %}class="active" aria-current="page"{% endif %}` pattern inside the site_header partial. Each page sets its `nav_active` block.

Existing pages currently render fine - just wrap them in the new shell without modifying their inner content blocks. Frontend redesign of the inner content lands in PR-082-085.

## Risk

Layout-level change affects every page render. Smoke test on local dev that every existing page (`/`, `/drives`, `/events`, `/audit`, `/drives/0/0`, `/controller/patrol-read`) still renders without 500 error.
