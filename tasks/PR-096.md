# PR-096: Align controller detail health snapshot to approved mockup

- Complexity: medium
- Depends on: PR-095
- Priority: 3
- Coder: any

## Problem

The controller detail page health snapshot diverged from the approved mockup. The mockup shows the state as large colored text beside a one-line summary, with the six metrics in a single compact inline wrap-row. The implementation renders the state and metrics as a `<dl>` definition-list with relabeled fields, producing a different, boxier look.

The rest of the controller detail page (live operations, cachevault, RoC chart, raid config, scheduled tasks, hardware identity, buzzer control, foreign config) matches the mockup structurally and is NOT changed here, except the degree-symbol format already handled in PR-095.

The drive detail page already matches the mockup (health snapshot with inline locate, sparkline, position diagram, fixed-height temp chart, identity, connection, advanced actions, replace). No drive-detail changes are needed beyond PR-095's degree symbol. This PR therefore focuses on the controller detail health snapshot.

## Approved mockup: controller health snapshot HTML (reproduce exactly)

```
<div class="health-snapshot {{ health_class }}">
  <div class="health-row1">
    <div class="health-state {{ health_class }}">{{ view_model.health.state }}</div>
    <div class="health-summary">{{ view_model.health.summary_text }}</div>
  </div>
  <div class="metrics-row">
    <div class="metric-item">
      <span class="metric-label">RoC Temp</span>
      <span class="metric-value">{% if view_model.health.roc_temperature_celsius is not none %}{{ view_model.health.roc_temperature_celsius }}&deg;C{% else %}N/A{% endif %}</span>
    </div>
    <div class="metric-item">
      <span class="metric-label">CacheVault</span>
      <span class="metric-value">{% if view_model.health.cv_capacitance_percent is not none %}{{ view_model.health.cv_capacitance_percent }}%{% else %}N/A{% endif %}</span>
    </div>
    <div class="metric-item">
      <span class="metric-label">BBU</span>
      <span class="metric-value">{{ view_model.health.bbu_status }}</span>
    </div>
    <div class="metric-item">
      <span class="metric-label">Mem ECC Errors</span>
      <span class="metric-value">{{ view_model.health.memory_ecc_errors_total }}</span>
    </div>
    <div class="metric-item">
      <span class="metric-label">Errors (24h)</span>
      <span class="metric-value">{{ view_model.health.errors_24h }}</span>
    </div>
    <div class="metric-item">
      <span class="metric-label">Uptime</span>
      <span class="metric-value">{{ view_model.health.uptime_text }}</span>
    </div>
  </div>
</div>
```

Where `health_class` is `"warn"` for WARNING, `"crit"` for CRITICAL, empty string for OPTIMAL (the same convention the current template already computes at its top).

Key differences from current implementation to apply:
- Replace the `<dl class="health-snapshot__metrics">` definition list with the `metrics-row` flex row of `metric-item` (label + value), as above.
- State becomes `health-state` large colored text in `health-row1` beside `health-summary`, not a `text-label` + `<strong>` stack.
- Metric labels match the mockup exactly: "RoC Temp", "CacheVault", "BBU", "Mem ECC Errors", "Errors (24h)", "Uptime" (NOT "RoC temperature", "CacheVault capacitance", "Memory ECC", "Errors in 24h", "App uptime").
- Keep the `section` wrapper and the "Health snapshot" section title heading.
