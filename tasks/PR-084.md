## Problem

The existing Drive detail page (`/drives/{e}:{s}`) uses the old layout with 9 information tiles plus 2 huge charts that grow uncontrollably. Mockup `drive-detail-v1.html` redesigns it: header with prev/next nav, 7 sections (Health snapshot with inline Locate + sparkline → Position → Temperature chart → Identity → Connection → Advanced Actions → Destructive Replace).

The view model `DriveDetailViewModel` lands in PR-077; the advanced action endpoints land in PR-079. This PR creates the templates, CSS, and routes wiring.

## Implementation notes

The error sparkline is rendered as inline SVG with 30 data points (or fewer if drive is younger). When all values are 0, the SVG line is flat at the bottom. When values grow, the line ramps up.

The backplane diagram (8 small slots) is a CSS Flexbox of 8 small boxes. The "this" slot has a different background color and bold text. Each slot links to its drive detail page; clicking on a different slot navigates without page reload (HTMX could be used but vanilla href is fine).

Advanced action buttons use POST forms with CSRF token. State-disabled buttons render as `<button disabled>` with title attribute explaining why.

The temperature chart fix (`chart-canvas-v2` class with fixed 220px height) is REUSED from PR-083. This is where the "huge charts" problem visibly disappears for the user.

Replace destructive card uses the same `destructive-card` CSS class from PR-083.

Migration of `pages/drive_detail.html` to `pages/drive_detail_v2.html` follows the v2 namespacing pattern. After PR-088 cleanup, the v2 suffix is dropped.
