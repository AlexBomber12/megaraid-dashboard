# PR-073: Enable coverage gate + branch coverage + ruff PGH

Branch: pr-073-coverage-gate
- Type: config
- Complexity: low
- Depends on: PR-071, PR-072
- Priority: 2
- Coder: any

## Problem

PR-071 and PR-072 bring line and branch coverage to 100%. Without a gate in CI, the next PR can regress without anyone noticing. This PR is the lock: it enables `--cov-fail-under=100`, `--cov-branch`, and `--cov-report=term-missing` as default pytest options. It also extends ruff's lint config to flag bare `# type: ignore` (no error code), and adds a small CI summary step that prints the coverage figure for visibility.

## Scope

In scope:
- `pyproject.toml` `[tool.pytest.ini_options]`: extend `addopts` with `--cov-fail-under=100 --cov-branch`.
- `pyproject.toml` `[tool.ruff.lint]`: add `PGH` to `select`.
- Verify the existing three `# type: ignore[code]` annotations still pass under PGH (they should: they all have explicit codes).
- A small note in `README.md` mentioning the 100% line + branch policy.
- A small note in `CONTRIBUTING.md` (if present) about the coverage gate.

Out of scope:
- Any test changes. PR-071 and PR-072 own those.
- Any production code changes.
- pre-commit config changes (the existing config will pick up the new rules automatically since it shells out to ruff and pytest).

## Implementation notes

The `--cov-fail-under=100` flag makes pytest exit non-zero if total coverage drops below 100%. The number applies to whichever coverage type is the default; with `--cov-branch` enabled, branch coverage is also tracked but pytest-cov reports a single combined "TOTAL" percentage. Verify behavior locally first:

```
python -m pytest
```

Expect: 100% in the terminal report, exit 0. If anything below 100%, exit non-zero with the message naming the offending file and percentage.

Adding `PGH` to ruff `select` enables three rules in the PGH category:
- `PGH003`: forbids bare `# type: ignore` (must specify error code).
- `PGH004`: forbids bare `# noqa`.
- `PGH005`: requires the right method on `unittest.mock`.

The existing three `# type: ignore[...]` annotations all use the bracketed-error-code form, so they pass PGH003. The two `# noqa: N818` annotations in `storcli/exceptions.py` also use the bracketed form, so they pass PGH004. No code changes needed.

If a future PR introduces a bare `# type: ignore`, ruff will flag it before merge, preserving the discipline established here.

The `addopts` line can become long; if it crosses a readability threshold, multi-line is fine:

```toml
addopts = """
  --cov=src/megaraid_dashboard
  --cov-report=term-missing
  --cov-branch
  --cov-fail-under=100
"""
```

(TOML supports triple-quoted strings; pytest joins on whitespace.)


CI (via the GitHub Actions workflow): same checks, must pass.

A deliberate regression check (do NOT commit):

```
# Add a `pass` statement somewhere unreachable
git commit -am "test regression"
python -m pytest
# Expect: FAIL with coverage below 100%
git reset HEAD~
```

This dry-run confirms the gate is wired.

## Success criteria

1. `python -m pytest` exits 0 with `TOTAL` showing 100% line and branch coverage.
2. `python -m pytest` exits non-zero if coverage drops (verified by dry-run regression).
3. `python -m ruff check .` passes with `PGH` rules active.
4. README and CONTRIBUTING document the policy.
5. CI runs end-to-end on the merge commit successfully.
6. `bash scripts/ci.sh` exits 0.
7. No file outside `pyproject.toml`, `README.md`, `CONTRIBUTING.md` is modified.
