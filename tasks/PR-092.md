# PR-092: Main page formatting polish (activity age, patrol read text, footer dedup, CSS cleanup)

Branch: pr-092-main-page-formatting-polish
- Type: ux
- Complexity: low
- Depends on: PR-091
- Priority: 3
- Coder: any

## Problem

The redesigned pages render with the correct structure but several display details diverge from the intended design. The data is present; the formatting is raw or duplicated. Four small fixes:

1. **Activity timeline age column shows the event category instead of a relative age.** `activity_timeline_v2.html` renders `event.category` (e.g. "temperature") in the slot meant for relative age (e.g. "3 days ago"). `RecentActivityItem` has `occurred_at: datetime` but no formatted age field.

2. **Controller card patrol-read line shows a raw ISO timestamp.** `controller_summary_card.html` renders `controller.last_patrol_read_completed_at | iso_utc` (raw "2026-05-12T...UTC"). The view model ALREADY provides `last_patrol_read_duration_text` and `next_patrol_read_in_text`, but the template ignores them. Intended: "Last patrol read May 12 (8h 14m) - Next in 4d 12h".

3. **Two footers render.** `layouts/base.html` renders a legacy `<footer class="site-footer">Version ... | Build ...</footer>` AND the new `system_health_bar.html` status bar. Only the status bar should remain. The legacy footer shows "Build unknown" when no build SHA is set.

4. **Orphaned `.chart-canvas` CSS.** The old `.chart-canvas` rule with `aspect-ratio: 16 / 6` (the cause of the original growing-chart bug) is still in `app.css` but no template references it; all charts now use `.chart-canvas-v2`. Remove the dead rule and its media-query variants.

## Scope

In scope:

### Fix 1: activity relative age

- Add a formatted age field to `RecentActivityItem` in `services/overview.py`: either a new field `age_text: str` populated by the loader, or a computed property. Prefer a field set at load time so the template stays logic-free, computed via the existing `_format_relative_time` helper.
- Update `_load_recent_activity` to populate it.
- Update `activity_timeline_v2.html`: the age slot renders `event.age_text` instead of `event.category`. (If category should still be shown somewhere, keep it, but the age column must show age. The mockup put age in that column.)

### Fix 2: patrol read human text

- Update `controller_summary_card.html` no-active-operations branch to use the existing view-model fields:
  - "Last patrol read {{ controller.last_patrol_read_duration_text }}" when present (the duration text should already encode the human date and duration; if it only encodes duration, also format `last_patrol_read_completed_at` to a short human date like "May 12" rather than raw ISO).
  - " - Next {{ controller.next_patrol_read_in_text }}" when present.
  - Fall back to "Last patrol read unknown" when no data.
- If `last_patrol_read_duration_text` does not currently include the date, add a `last_patrol_read_completed_text` field to `ControllerSummaryViewModel` formatted as a short human date, and use it. Keep formatting in the view model, not the template.

### Fix 3: remove duplicate footer

- In `layouts/base.html`, remove the legacy `<footer class="site-footer">...Version ... | Build ...</footer>` block. Keep the `{% block status_bar %}` mechanism that renders `system_health_bar.html`.
- Remove now-unused `build_sha` / `app_version` template globals ONLY if nothing else references them (grep first; the status bar still shows version via the view model, which is separate).
- Remove the `.site-footer` CSS if no longer used.

### Fix 4: remove orphaned chart CSS

- In `static/css/app.css`, remove the `.chart-canvas` rule (the one with `aspect-ratio: 16 / 6; min-height: 280px`) and its responsive `@media` variants that reference `.chart-canvas`.
- Keep `.chart-canvas-v2` (the fixed-height rule in active use).
- Grep templates to confirm no `class="chart-canvas"` (non-v2) remains before deleting.

Out of scope:
- BBU metric tile on the controller card (intentionally merged into CacheVault; not changing).
- Collector "never" status (handled separately if it proves to be a bug).
- Any structural or layout change.
- Drive detail and controller detail pages (they match the design).
