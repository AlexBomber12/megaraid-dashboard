# PR-069: consolidate CSRF whitelist + unify audit-failure HTTP response

Branch: pr-069-csrf-whitelist-audit-consistency
- Type: bugfix
- Complexity: low
- Depends on: none
- Priority: 2
- Coder: any

## Problem

Two correctness findings from the L2 audit, both about consistency of behavior across modules:

**Finding 1 - CSRF whitelist drift:**
`src/megaraid_dashboard/web/csrf.py` (around lines 16-17 and 82-83) defines its own local `_WHITELIST_EXACT` and `_WHITELIST_PREFIX` constants instead of importing from `web/_whitelist.py`. The other two middlewares (`auth.py`, `rate_limit.py`) DO use `_whitelist.is_whitelisted()`. This creates drift risk: if a new whitelisted path is added (e.g. `/metrics-shim`), and the developer updates `_whitelist.py` but forgets `csrf.py`, the CSRF middleware will still demand a token for that path while auth and rate-limit let it through. The task file for PR-014 explicitly said "Factor the whitelist constants into web/_whitelist.py so all three middlewares share the same list". The intent existed; the implementation drifted.

**Finding 2 - Audit-failure HTTP response inconsistency:**
When an operator action (locate, replace, maintenance, patrol-read, consistency-check) cannot be recorded in the `events` audit log due to `SQLAlchemyError`:
- Replace endpoints (`/drives/{e}:{s}/replace/*`) return **500** with `audit_failure_body`.
- Locate endpoints (`/drives/{e}:{s}/locate/*`) return **200 OK** and silently `LOGGER.exception(...)` (around `routes.py:482`).
- Patrol-read, consistency-check: TBD - verify during implementation.

The operator-facing contract is: "if you got 200, the action was recorded in audit". The locate endpoint violates this. An operator who acts on locate but whose audit row didn't persist has no way to know.

For real risk: small, because the same SQL session also writes other state alongside the audit row; if audit fails, likely other writes also failed. But the inconsistency is a bug regardless.

## Scope

In scope:
- Replace local whitelist constants in `web/csrf.py` with `from megaraid_dashboard.web._whitelist import is_whitelisted` (or `WHITELIST_EXACT`, `WHITELIST_PREFIX` depending on what csrf needs).
- Unify audit-failure HTTP response across ALL mutating endpoints. Recommendation: return **500** with a JSON body matching the pattern already used in replace endpoints. Document the contract in the route handler docstrings.
- Add a shared helper `_record_operator_action_or_500(...)` in `web/routes.py` (or `services/audit.py` if cleaner) that wraps the try/except pattern. Convert each mutating endpoint to use it. This eliminates the drift surface for future endpoints.
- Tests: every mutating endpoint, when audit insertion fails (mock the session.execute to raise SQLAlchemyError), returns 500 with the documented body.

Out of scope:
- Adding new audit features. Just unify the existing pattern.
- Changing the audit row schema or the storage backend.

## Implementation notes

The audit-failure unified helper pattern:
```python
def _record_operator_action_or_500(
    session: Session,
    *,
    request: Request,
    category: str,
    summary: str,
    before: dict[str, Any] | None = None,
    after: dict[str, Any] | None = None,
) -> Response | None:
    try:
        record_operator_action(
            session,
            request=request,
            category=category,
            summary=summary,
            before=before,
            after=after,
        )
        session.commit()
        return None  # success, caller continues
    except SQLAlchemyError as exc:
        session.rollback()
        LOGGER.exception("operator_action_audit_failed", category=category)
        return JSONResponse(
            {"error": "audit log write failed; action not recorded"},
            status_code=500,
        )
```

Call sites:
```python
audit_response = _record_operator_action_or_500(
    session, request=request, category="drive_locate_start",
    summary=f"Locate started for {enclosure}:{slot}",
)
if audit_response is not None:
    return audit_response  # 500 with body
# ... proceed with storcli call
```

Note: the pattern returns the early-exit response or None. Caller checks for None to continue. This keeps each handler readable.

CSRF whitelist consolidation: trivial import + use. No behavior change for existing whitelisted paths (`/healthz`, `/favicon.ico`, `/static/*`).
