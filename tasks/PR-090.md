# PR-090: Fix controller detail 500 (wrong scheduler reference)

Branch: pr-090-fix-controller-detail-500
- Type: bugfix
- Complexity: low
- Depends on: PR-089
- Priority: 1
- Coder: any

## Problem

`GET /controller` returns HTTP 500 in production. Main page, drives, drive detail, RoC history endpoint, and HTMX polling all work. Only controller detail is broken.

Production traceback:

```
AttributeError: 'AsyncIOScheduler' object has no attribute 'get_last_collector_run_at'
  web/routes.py _load_controller_detail
  services/controller_detail.py load_controller_detail_view_model
  services/overview.py _load_system_health
    collector_last_run_at = None if scheduler is None else scheduler.get_last_collector_run_at()
```

Root cause: `_load_system_health` expects a `_CollectorStateProvider` (a Protocol exposing `get_last_collector_run_at()`). The `services.scheduler` module satisfies this protocol via its module-level `get_last_collector_run_at()` function.

Two callers disagree on what to pass as `scheduler`:

- `_load_main_page` passes `scheduler=scheduler_state`, where `scheduler_state` is the module alias `from megaraid_dashboard.services import scheduler as scheduler_state`. The module HAS the function. Main page works.
- `_load_controller_detail` passes `scheduler=getattr(request.app.state, "scheduler", None)`, which is the raw APScheduler `AsyncIOScheduler` instance. That object does NOT have the method. Controller detail crashes.

PR-076 used the wrong reference. The one-line fix: pass the module alias `scheduler_state`, identical to what `_load_main_page` does.

## Scope

In scope:

1. In `web/routes.py`, function `_load_controller_detail`: change the `scheduler` argument passed to `load_controller_detail_view_model` from the raw `request.app.state.scheduler` to the module alias `scheduler_state` (the same value `_load_main_page` passes).
   - Remove the now-unused local `scheduler = getattr(request.app.state, "scheduler", None)` line if it is no longer referenced.
   - Confirm `scheduler_state` is already imported at module top (it is, used by `_load_main_page`).

2. Add a regression test that exercises `_load_system_health` (or the controller detail loader) with the SAME object type that production passes, so the mismatch cannot recur.

## Why existing tests missed this

The PR-076 unit tests passed a mock or the module that has `get_last_collector_run_at()`. They never passed a raw `AsyncIOScheduler`. The regression test must assert that the object actually handed to the loader in the route satisfies the protocol, OR test the route end to end so the real wiring is exercised.

## Files to modify

`src/megaraid_dashboard/web/routes.py`:
- `_load_controller_detail`: pass `scheduler=scheduler_state` instead of the raw app-state scheduler.

## Files to create or extend

`tests/test_web/test_controller_detail_page.py` (extend):
- Add `test_controller_detail_renders_200_with_real_scheduler_wiring`: build the app via the real factory (or a fixture that wires `app.state` the way production does) and GET `/controller`, asserting HTTP 200, not 500. This catches the scheduler-type mismatch that unit-level VM tests missed.
- If a full-app fixture already exists in the test suite (the e2e or integration fixtures), prefer reusing it so the test exercises the genuine route wiring.

## Files NOT to touch

- `services/controller_detail.py` (the loader signature is correct; the bug is the caller).
- `services/overview.py` (`_load_system_health` is correct; it documents the protocol).
- `services/scheduler.py` (the module-level function is correct).
- Templates.
- Any other route.

## Implementation notes

The fix is one line. Do NOT change `_load_system_health` to accept a raw APScheduler; the protocol design is intentional (the scheduler module is the state provider, not the APScheduler instance). Fix the caller to match the working `_load_main_page` pattern.

Verify after the change that `_load_main_page` and `_load_controller_detail` now pass the SAME `scheduler_state` value, so the two pages are consistent.

## Risk

One-line caller fix plus a regression test. Lowest-risk possible change. The danger is fixing it the wrong way (changing the protocol or the loader instead of the caller); the scope explicitly forbids that.

Smoke test after merge: `GET /controller` returns 200 and renders all sections.
