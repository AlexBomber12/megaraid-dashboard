# PR-082: Frontend Main page (controller summary + drive grid + activity + status bar)

Branch: pr-082-frontend-main-page
- Type: feature
- Complexity: medium
- Depends on: PR-081
- Priority: 2
- Coder: any

## Problem

The Overview page (`/`) is being replaced with the new layout per design mockup `dashboard-mockup-v4.html`: one large controller tile (clickable, leads to `/controller`), 8-drive backplane grid (each tile clickable, leads to `/drives/{e}/{s}`), recent activity timeline (10 events), bottom status bar.

The view model `MainPageViewModel` lands in PR-075. This PR creates the templates and CSS to render it.

## Scope

In scope:

1. New template `templates/pages/main.html` (replaces `pages/overview.html`):
   - Page title block
   - Controller summary card (using `controller` field of view model)
   - Drive grid section (8 tiles in row, using `drive_grid.tiles`)
   - Recent activity section (using `recent_activity`)
   - Status bar block (uses base layout slot, populated from `system_health`)
   - Set `nav_active=overview`

2. New partial `templates/partials/controller_summary_card.html`:
   - Reusable for the controller card on the main page.
   - Renders state badge, model line, metrics row, operations row.
   - Click target: `/controller`.
   - Handles all three states (OPTIMAL green, WARNING orange, CRITICAL red border).
   - Operations row: when idle shows "No active operations" + last/next text; when running shows "Patrol Read 47% · Consistency Check 12%" with hover tooltips.

3. New partial `templates/partials/drive_grid.html`:
   - 8 tiles in CSS Grid (`grid-template-columns: repeat(8, 1fr); gap: 8px`).
   - Each tile renders slot label, state text (color per severity), temperature (color per severity).
   - Error badge (iOS-style floating top-right corner) when `error_badge_count` is not None.
   - Each tile is an `<a>` with `href` from `tile.detail_url`.

4. New partial `templates/partials/activity_timeline.html` (or extend existing):
   - 10 rows, each with date · severity badge · summary · age.
   - Hover state for click affordance.
   - "All events →" link to `/events`.

5. New partial `templates/partials/system_health_bar.html`:
   - Bottom status bar with Notifier / Collector / DB / version.
   - Uses `SystemHealthViewModel` fields.
   - Filled from `{% block status_bar %}` slot in base layout.

6. CSS additions to `static/css/app.css` (with v2 namespacing where conflicts):
   - `.controller-card-v2`, `.drive-grid-v2`, `.drive-tile-v2`, `.drive-error-badge-v2`, `.activity-list-v2`, `.activity-item-v2`, `.status-bar-v2`.
   - Match mockup design tokens.
   - Drive error badge: `position: absolute; top: -11px; right: -8px; border: 2px solid var(--color-surface);` for the iOS-style floating effect.

7. Route `/` updated to use the new view model loader and template:
   - `web/routes.py`: change the existing `@router.get("/")` handler to call `load_main_page_view_model` (from PR-075) and render `pages/main.html`.
   - Keep `/partials/overview` endpoint intact for backward compatibility until PR-088 cleanup; it can render the same template's drive grid partial OR the legacy template.

Out of scope:
- HTMX 30s polling integration (PR-086).
- Drive detail page (PR-084).
- Controller detail page (PR-083).
- Removing the old `pages/overview.html` (PR-088 cleanup).

## Implementation notes

The drive tile needs `overflow: visible` on the `<a>` itself for the iOS-style badge to float outside. Verified during mockup development. Use the v2 class to avoid touching existing `.drive-tile` styles (if any).

Activity timeline items should be clickable rows that link to a future event detail page. For now, link to `/events` with the event's id as query param.

Status bar uses the `{% block status_bar %}` slot from PR-081 base layout. If status_bar block is empty, the slot is not rendered.

Operations row in controller card: when both Patrol Read and Consistency Check are running, render "Patrol Read 47% · Consistency Check 12%" with tooltips per item. Tooltip implementation: pure CSS via `data-tooltip` attribute, no JS.

## Risk

Replacing the main page is the most user-visible change in the entire redesign. Smoke test in production after merge:
- `/` still loads 200.
- Drive grid renders with correct slot labels.
- Click on drive tile leads to drive detail page (still renders old drive_detail.html until PR-084).
- Click on controller card leads to /controller (may 404 until PR-083).
