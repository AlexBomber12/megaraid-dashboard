# PR-088b: Rewrite mixed overview test files after legacy removal

Branch: pr-088b-rewrite-mixed-tests

- Complexity: medium
- Depends on: PR-088a
- Priority: 3
- Coder: any

## Problem

PR-088a removed the legacy overview production code and left four MIXED test files marked with a module-level `pytest.skip("rewritten in PR-088b")`. These files import and exercise BOTH removed legacy symbols AND live symbols that must keep their coverage. This PR removes the skip markers and surgically deletes only the legacy-targeting test functions and imports, preserving every test that exercises live code.

## Principle

A test function is LEGACY (delete it) if and only if it exercises a symbol removed in PR-088a. A test function is LIVE (keep it) if it exercises a symbol that still exists.

## Implementation notes

Work one file at a time. For each file:
1. Remove the module-level `pytest.skip` from PR-088a.
2. Run the file's imports mentally against the removed-symbol list. Any `import` of a removed symbol must go.
3. Delete each test function that calls a removed symbol.
4. Run `python -m pytest tests/test_services/test_overview_<name>.py` and confirm green.
5. Run ruff to catch unused imports.

When in doubt whether a test is legacy or live, check which overview symbol it calls and match against the two lists in the Principle section. The symbol classification wins over the per-file hints if they ever disagree (the hints were written from a snapshot and a function may have moved).

If deleting `test_overview_tooltip.py` entirely, that is a single file deletion (below the tier-2 guardrail threshold of 5).

Do NOT delete the `_insert` / `_snapshot` fixtures in test_overview.py; test_overview_branches.py imports them. If they reference removed symbols internally, adapt them minimally to construct snapshots without the removed classes (they likely build StorcliSnapshot directly, which is live).

## Risk

Surgical test edits across four files. The danger is deleting a live test by mistake, dropping coverage on live code. Mitigations:
- Coverage gate at 100% will FAIL CI if any live line loses its only covering test, surfacing the mistake immediately.
- The symbol-classification principle gives a deterministic keep/delete rule.
- Pure-live files are explicitly off-limits.

After this PR, the coverage gate proves correctness: if it stays green at 100%, no live coverage was lost.

## Success criteria

1. ruff/mypy/format pass (no unused imports left behind).
2. Full test suite passes with NO skipped overview modules (all skips from PR-088a removed).
3. Coverage stays at 100% on all live code.
4. `tests/test_services/test_overview_activity.py` and `test_overview_controller_health.py` are byte-for-byte unchanged.
5. PR description lists, per file, which test functions were deleted and which kept, with the triggering removed-symbol for each deletion.
6. No production code modified; no pure-live test file touched.
