## Problem

PR-074 subdivision chunk **c**. Covers scenarios that require state setup (DB writes, snapshot fixtures, CSRF token round-trip). This is the most complex of the four e2e sub-PRs because each scenario requires a known DB state plus precise request shaping.

## Scope

In scope:
- `tests/e2e/test_csrf_flow.py`: CSRF token round-trip. GET issues `__Host-csrf` cookie; POST with matching header succeeds; POST without header gets 403.
- `tests/e2e/test_maintenance_flow.py`: Maintenance start (with duration), banner appears; stop, banner disappears.
- `tests/e2e/test_locate_flow.py`: Drive locate start with confirmation; stop with confirmation.
- New fixture `snapshot_with_drives` in conftest: inserts a minimal controller snapshot with 2-3 drives into the fresh DB so locate/replace tests have something to operate on.

Out of scope:
- Replace wizard, static, events scenarios + CI workflow (PR-074d).
- Real storcli calls. Tests mock storcli via the STUB script (already set up in PR-074a) returning fixed-success exit code.

```python
import pytest

@pytest.mark.asyncio
async def test_csrf_post_requires_header(authenticated_page, live_server):
    # First GET to obtain the cookie
    response = await authenticated_page.request.get(f"{live_server}/")
    assert response.status == 200
    # Inspect set-cookie header
    headers = response.headers
    cookie_header = headers.get("set-cookie", "")
    assert "__Host-csrf=" in cookie_header

    # POST without X-CSRF-Token: expect 403
    response = await authenticated_page.request.post(
        f"{live_server}/maintenance/start",
        data={"duration_minutes": "5"},
    )
    assert response.status == 403

@pytest.mark.asyncio
async def test_csrf_post_with_matching_header_succeeds(
    authenticated_page, live_server, fresh_db
):
    # GET to capture cookie
    await authenticated_page.goto(f"{live_server}/")
    # Read cookie via page evaluate
    cookies = await authenticated_page.context.cookies(f"{live_server}/")
    csrf_cookie = next(c for c in cookies if c["name"] == "__Host-csrf")
    token = csrf_cookie["value"]

    # POST with X-CSRF-Token header matching cookie
    response = await authenticated_page.request.post(
        f"{live_server}/maintenance/start",
        data={"duration_minutes": "5"},
        headers={"X-CSRF-Token": token},
    )
    assert response.status in (200, 303)  # success or redirect
```

```python
async def test_maintenance_start_shows_banner(
    authenticated_page, live_server, fresh_db

    await authenticated_page.goto(f"{live_server}/")
    cookies = await authenticated_page.context.cookies(f"{live_server}/")

    await authenticated_page.goto(f"{live_server}/")

    assert "maintenance" in content.lower()
```

## Implementation notes

CSRF cookie parsing: Playwright stores cookies in the context after the first GET. `context.cookies(url)` returns the list; find the `__Host-csrf` entry and extract `.value`.

The `__Host-` prefix requires HTTPS in some browsers but Playwright handles HTTP localhost as a special case. If the test fails to find the cookie, verify the cookie was actually set in the response headers (PR-074a's smoke test confirms server-side setup is right).

The `snapshot_with_drives` fixture writes directly to DB. This bypasses the normal storcli-collector flow but exercises the same endpoint logic. Verify the DB models match (snapshot from PR-067/068 changes to schema). If models drift, fixture needs update.

For locate POST: the stub storcli script from PR-074a returns success on any args. The endpoint should accept the request, write an audit event, return success. If it returns 502 (storcli failed) or 500 (audit failed), inspect the stub script implementation.

## Risk

DB state setup means tests are not pure-stateless. Each test must use `fresh_db` or `snapshot_with_drives` (function-scoped) to avoid cross-test pollution.
