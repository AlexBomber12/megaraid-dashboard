## Problem

The new Drive detail page (`/drives/252:0`) needs a unified view model covering: health snapshot with inline locate buttons + error sparkline; physical position (with backplane diagram data); temperature history chart (existing data); identity (9 fields); connection (8 fields); advanced actions (Mark UBad/UGood/Spin Down/Hot Spare); destructive replace flow.

Some data exists in existing modules (`services/drive_history.py` for temperature/error series, `services/drive_actions.py` for storcli commands). What's missing is the assembled ViewModel with new fields (sparkline aggregation for 30d, position diagram data, action URL/availability decisions).

## Scope

In scope (new module `services/drive_detail.py`):

1. `DriveHealthSnapshot` dataclass:
   - `state: str` (ONLINE/REBUILDING/FAILED/MISSING/UBAD/UGOOD/etc.)
   - `state_severity: str` (optimal/warning/critical)
   - `state_subtitle: str` (e.g. "Member of VD 0. RAID 5. DG 0.")
   - `summary_text: str` (e.g. "Drive functioning normally. 1 historical media error (recoverable).")
   - `temperature_celsius: int | None`
   - `temperature_severity: str` (optimal/warning/critical)
   - `smart_status: str` ("OK" or "ALERT")
   - `smart_severity: str`
   - `predictive_failure_count: int`
   - `can_locate_start: bool`
   - `can_locate_stop: bool`
   - `locate_active: bool`
   - `locate_start_url: str`
   - `locate_stop_url: str`

2. `ErrorSparkline` dataclass:
   - `current_total: int` (sum of all error types)
   - `media_errors: int`
   - `other_errors: int`
   - `bbm_errors: int`
   - `shield_counter: int`
   - `points: list[ErrorSparklinePoint]` (30 daily points, each with date + total count + last incremental delta)
   - `meta_text: str` (e.g. "Media 1 / Other 0 / BBM 0 / Shield 0")

3. `PhysicalPosition` dataclass:
   - `enclosure: int`
   - `slot: int`
   - `dg_span_row_text: str` (e.g. "0 : 0 : 4")
   - `port_text: str` (e.g. "Port 0-3 x1 (port 7)")
   - `backplane_layout: list[BackplaneSlot]` (8 entries with slot_label, is_this, severity)

4. `BackplaneSlot` dataclass (used inside PhysicalPosition.backplane_layout):
   - `slot_label: str` (e.g. "S0")
   - `enclosure_id: int`
   - `slot_id: int`
   - `is_this: bool` (highlight in diagram)
   - `severity: str` (color hint)
   - `detail_url: str`

5. `DriveIdentity` dataclass (9 fields):
   - model, serial_number, manufacturer_text ("ATA (SATA)" or "SAS"), firmware_revision
   - wwn, media_type (HDD/SSD)
   - raw_size_text, coerced_size_text, logical_sector_size_text

6. `DriveConnection` dataclass (8 fields):
   - interface_text ("SATA 6Gb/s"), device_speed_text, link_speed_text
   - link_speed_is_degraded: bool (true when device_speed != link_speed)
   - ncq_enabled_text, sas_address, connector_text, sequence_number
   - wide_port_text

7. `AdvancedActionButton` dataclass:
   - `label: str` (e.g. "Mark as UBad")
   - `url: str`
   - `is_destructive: bool`
   - `is_enabled: bool` (false when state forbids the transition)
   - `disabled_reason: str | None`

8. `ReplaceWizardState` dataclass:
   - `can_begin: bool` (always true unless already mid-flow)
   - `current_step: int | None` (1, 2, 3 if mid-flow, None otherwise)
   - `begin_url: str`
   - `resume_url: str | None`
   - `warning_text: str` (constant copy from mockup)

9. `DriveDetailViewModel` dataclass combining all:
   - `page_title: str` (e.g. "Slot 252:0 (S0)")
   - `page_subtitle: str`
   - `prev_drive_url: str | None`
   - `next_drive_url: str | None`
   - `health: DriveHealthSnapshot`
   - `error_sparkline: ErrorSparkline`
   - `position: PhysicalPosition`
   - `temperature_chart: DriveTemperatureSeries` (existing class from drive_history.py)
   - `identity: DriveIdentity`
   - `connection: DriveConnection`
   - `advanced_actions: list[AdvancedActionButton]`
   - `replace: ReplaceWizardState`
   - `system_health: SystemHealthViewModel` (reuse from PR-075)
   - `updated_at: datetime`
   - `auto_refresh_seconds: int`

10. Loader `load_drive_detail_view_model(session, *, enclosure_id, slot_id, settings, app_version, range_days=30) -> DriveDetailViewModel`.

11. Helper `_load_error_sparkline(session, *, serial_number, days)` aggregating per-day error count growth from drive_temperature_history or pd_snapshots.

12. Helper `_load_backplane_layout(session, *, this_enclosure, this_slot)` returning 8 BackplaneSlot for the same enclosure.

Out of scope:
- New endpoints. PR-084 wires the route.
- Advanced action mutating endpoints (PR-079).
- Templates (PR-084).

## Implementation notes

Sparkline aggregation strategy: query `pd_snapshots` for this serial, group by day, take latest snapshot per day, compute error count at that point. The "incremental delta" tells if errors grew on that day.

For prev/next drive URLs: query distinct (enclosure, slot) pairs for this controller, sort, find current index, compute previous/next. Wrap-around: at first slot, prev is None (not last slot); at last, next is None.

For backplane layout, reuse `DriveGridTileViewModel.tile_severity` computation logic from PR-075. To avoid duplication, extract that severity logic into a small helper in `services/overview.py` (e.g. `compute_drive_tile_severity(pd_snapshot, settings) -> str`) and import it from both modules.

For replace wizard state.current_step: read the latest operator_action audit event for this drive. If category in {drive_replace_offline, drive_replace_insert_pending}, set current_step accordingly. If category is drive_replace_completed or no event, current_step is None.
