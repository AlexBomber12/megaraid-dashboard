## Problem

## Implementation notes

The "huge charts" fix lives here per Q2 decision (frontend series). Implement as `.chart-canvas-v2 { height: 220px; max-height: 280px; }` and use that class for the new RoC chart. The existing `.chart-canvas` selector stays for drive_detail until PR-084 migrates.

RoC chart datafetch: vanilla JS via `fetch()`. No new JS framework. Add a small script block at the bottom of `roc_history_chart.html` that:
1. On DOMContentLoaded, fetches `/controller/roc-history?range_hours=24`.
2. Calls `new Chart(canvas, {...})` with the data.
3. Wires range tab clicks: fetch + destroy old chart + create new.

Use existing Chart.js (`static/vendor/chart.min.js`).

Buzzer button forms: each is a `<form method="post" action="..." class="inline-form">` containing CSRF input + submit button. Standard HTMX would be nicer but this is fine since the user does not need partial swap (full page reload after silence is acceptable, since the buzzer state changes).

Foreign config: similar form pattern. Import + Clear are mutually exclusive (show one or the other based on foreign_config.present); Clear has a confirmation dialog (use `onsubmit="return confirm('Clear foreign config?');"`).
