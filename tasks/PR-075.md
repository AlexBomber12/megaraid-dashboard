# PR-075: ViewModel for redesigned Main page (controller summary + drive grid + system health)

Branch: pr-075-main-page-viewmodel
- Type: feature
- Complexity: medium
- Depends on: PR-074d
- Priority: 2
- Coder: any

## Problem

The dashboard is being redesigned around an MSM-replacement spatial layout: one controller summary tile + 8 drive tiles in backplane order + activity timeline + bottom status bar. The existing `OverviewViewModel` in `services/overview.py` is built around the old strip-of-tiles layout (`OverviewStripSection` with `StripTileViewModel` items for Controller/VD/RAID/BBU/MaxTemp/RoC). The new layout needs different aggregations.

This PR creates the backend view model only. Frontend templates land in PR-082. The old `OverviewStripSection` MUST keep working so the existing page continues to render until PR-082 replaces it.

## Scope

In scope (new code in `services/overview.py`):

1. New `ControllerSummaryViewModel` dataclass with:
   - `state: str` (OPTIMAL/WARNING/CRITICAL, derived from `derive_controller_health`)
   - `model: str` (e.g. "LSI MegaRAID SAS 9270CV-8i")
   - `serial: str`
   - `raid_summary: str` (e.g. "RAID 5 (1 VD, 8 PD)")
   - `roc_temperature_celsius: int | None`
   - `cv_capacitance_percent: int | None`
   - `bbu_status: str` (e.g. "N/A" when CV-only, "Optimal" when BBU present)
   - `errors_24h: int` (count of warning+critical events in last 24h)
   - `active_operations: list[ActiveOperation]` where ActiveOperation has `name`, `progress_percent | None`, `tooltip`
   - `last_patrol_read_completed_at: datetime | None`
   - `last_patrol_read_duration_text: str | None` (e.g. "8h 14m")
   - `next_patrol_read_in_text: str | None` (e.g. "4d 12h")

2. New `DriveGridTileViewModel` dataclass with:
   - `slot_label: str` (e.g. "S0")
   - `enclosure_id: int`
   - `slot_id: int`
   - `temperature_celsius: int | None`
   - `temperature_state: str` (optimal/warning/critical, derived from configured thresholds)
   - `state_text: str` (Onln, Failed, Rebld, UBad, UGood, Missing)
   - `state_severity: str` (optimal/warning/critical)
   - `tile_severity: str` (WORST of temperature_state and state_severity)
   - `error_badge_count: int | None` (sum of media_errors + other_errors + bbm_errors + predictive_failures, None if all zero)
   - `detail_url: str` (e.g. "/drives/252:0")

3. New `DriveGridViewModel` dataclass:
   - `tiles: list[DriveGridTileViewModel]` (sorted by enclosure asc, slot asc)
   - `worst_severity: str` (optimal/warning/critical for header tinting if needed)

4. New `SystemHealthViewModel` dataclass for the bottom status bar:
   - `notifier_ok: bool`
   - `collector_last_run_at: datetime | None`
   - `collector_last_run_text: str` (e.g. "3 min ago", "never")
   - `db_size_human: str` (e.g. "6.7 MB")
   - `app_version: str`

5. New `MainPageViewModel` dataclass combining all of the above:
   - `controller: ControllerSummaryViewModel`
   - `drive_grid: DriveGridViewModel`
   - `recent_activity: list[RecentActivityItem]` (reuse existing class, 10 latest)
   - `system_health: SystemHealthViewModel`
   - `updated_at: datetime`
   - `auto_refresh_seconds: int` (config-driven, default 30)

6. New loader function `load_main_page_view_model(session, *, settings, scheduler, collector_enabled, app_version) -> MainPageViewModel` that orchestrates all the loads.

7. Helper functions (module-private with leading underscore):
   - `_load_controller_summary` (reuses existing `_get_latest_overview_snapshot` and `derive_controller_health`)
   - `_load_drive_grid` (reuses snapshot data, computes tile severities)
   - `_load_system_health` (computes notifier health from `services/notifier.py` state, collector last-run from scheduler, db size from `os.path.getsize`)
   - `_format_relative_time` (returns "3 min ago", "2 hours ago", etc.)
   - `_format_db_size` (bytes to human string)

Out of scope:
- Modifying or removing `OverviewStripSection`, `StripTileViewModel`, `OverviewViewModel` and their loaders. Frontend still uses them. PR-082 will remove after frontend migration.
- New endpoints. PR-082 wires the templates that call `load_main_page_view_model`.
- New DB queries or migrations. All data is already in `controller_snapshots`, `pd_snapshots`, `vd_snapshots`, `events` tables.

## Implementation notes

Severity priority for active operations (Q3 from design discussion): rebuild > consistency check > patrol read > foreign config import. Implement as a list of `ActiveOperation` sorted by this priority. If only one op is running, list has length 1. If none, empty list (template renders "No active operations").

Tooltip text for ActiveOperation should match the mockup pattern: "VD 0, started 18:15 - ETA 2h 12m". Compute ETA from progress + elapsed time if possible; if not, just show "ETA unknown".

Active operations come from existing services: `patrol_read.load_state`, `consistency_check.load_state`. Reuse, do not reimplement. If these return None (no controller snapshot), pass through as empty list.

Temperature thresholds for drives are already configured in `Settings` (verify exact name). Use settings, do not hardcode.

For `_format_relative_time`, prefer `humanize` library if already a dep; otherwise small helper without new deps.

For `_format_db_size`, simple helper that picks B/KB/MB/GB based on magnitude.

For `errors_24h`, query `events` table for `severity IN ('warning', 'critical') AND created_at > now - 24h`.

The legacy `_load_recent_activity` already exists with limit=8; new view model needs 10. Either change the legacy limit (verify no test asserts 8 hard-coded), or add a parameter `limit: int = 8` to the existing helper and pass 10 from the new loader. Adding a parameter is safer.
