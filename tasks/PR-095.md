# PR-095: Use degree symbol for all temperatures (match mockup)

Branch: pr-095-degree-symbol-global
- Type: ux
- Complexity: low
- Depends on: PR-094
- Priority: 3
- Coder: any

## Problem

Temperatures render as "76 C" (number, space, bare C) across the app. The approved mockups use "76°C" (number, degree symbol, C, no space) everywhere. This PR sweeps the format to match the mockup.

PR-094 already fixes the controller summary card RoC. This PR covers the remaining template locations.

## Confirmed locations rendering " C" (number space C)

- `templates/partials/drive_grid.html` line ~26: `{{ tile.temperature_celsius }} C`
- `templates/partials/drive_detail/health_snapshot.html` line ~60: `{{ view_model.health.temperature_celsius }} C`
- `templates/partials/controller_detail/health_snapshot.html` line ~15: `{{ view_model.health.roc_temperature_celsius }} C`
- `templates/partials/controller_detail/cachevault.html` line ~11: `{{ view_model.cachevault.temperature_celsius }} C`
- (controller_summary_card.html is handled in PR-094; if not yet merged, fix it here too, but PR-094 is the dependency so it should already be done.)

## Out of scope (do NOT change)

- `templates/partials/drive_charts.html` headers "Avg C / Min C / Max C": these are TABLE COLUMN HEADERS, not value renderings. Leave them as-is (or, if desired, change to "Avg °C" etc., but this is optional and not required; default to leaving unchanged).
- Any numeric chart axis labels rendered by Chart.js JavaScript (out of scope; charts handle their own formatting).

## Scope

In scope:

1. In each template location above, change the rendering from `{{ value }} C` to `{{ value }}&deg;C` (the `&deg;` HTML entity produces the degree symbol; immediately followed by `C`, no space). Preserve the surrounding `{% if ... is not none %}...{% else %}N/A{% endif %}` guards exactly; only the unit format changes.

Example transform:
- Before: `{% if x is not none %}{{ x }} C{% else %}N/A{% endif %}`
- After: `{% if x is not none %}{{ x }}&deg;C{% else %}N/A{% endif %}`

2. Optionally, to avoid future drift, introduce a small Jinja filter `celsius` registered in `web/templates.py` that formats an int as `f"{value}\u00b0C"` and renders empty/N/A for None, then use `{{ value | celsius }}` at each site. This is the more sustainable approach (single source of the format). If introducing the filter, cover it with a unit test. If the filter adds risk or scope creep, the inline `&deg;C` change is acceptable.

Prefer the filter approach for sustainability, but either satisfies the requirement.

## Implementation notes

The degree symbol must be the proper Unicode degree sign (U+00B0). Use the `&deg;` HTML entity in templates, or `\u00b0` in the Python filter. Do not use a masculine ordinal or other lookalike.

Confirm no double-formatting: if PR-094 already changed controller_summary_card to `&deg;C`, do not touch it again here.

After the change, every temperature on every page reads like "42°C", matching the mockups.

## Risk

Pure presentation format change. The only risk is a test that hard-asserted the old " C" format; update those.
