# PR-079: Drive advanced action endpoints (Mark UBad/UGood/Spin Down/Hot Spare)

Branch: pr-079-drive-advanced-endpoints
- Type: feature
- Complexity: medium
- Depends on: PR-078
- Priority: 3
- Coder: any

## Problem

The new Drive detail page (per PR-077 DriveDetailViewModel.advanced_actions) needs four advanced operator actions. None exist as endpoints today. Each requires a storcli wrapper plus an audited POST endpoint following the same pattern as buzzer endpoints from PR-078.

These actions are LESS commonly used than locate/replace, but important for: marking a flaky drive UBad to force the controller to ignore it; reversing that decision when the drive comes back; spinning down a drive for transport; designating a drive as hot spare for the array.

## Scope

In scope:

1. New storcli command builders in `services/drive_actions.py`:
   - `build_mark_unconfigured_bad_command(enclosure, slot) -> list[str]` returning `["/c0/e{enc}/s{slot}", "set", "bad"]`
   - `build_mark_unconfigured_good_command(enclosure, slot) -> list[str]` returning `["/c0/e{enc}/s{slot}", "set", "good"]`
   - `build_spin_down_command(enclosure, slot) -> list[str]` returning `["/c0/e{enc}/s{slot}", "spindown"]`
   - `build_make_hot_spare_command(enclosure, slot, dg_id) -> list[str]` returning `["/c0/e{enc}/s{slot}", "add", "hotsparedrive", "dgs=" + str(dg_id)]`

2. State machine validators in `services/drive_actions.py`:
   - `can_mark_ubad(current_state: str) -> bool`: True only if state is UGood (not Onln/Failed/etc).
   - `can_mark_ugood(current_state: str) -> bool`: True only if state is UBad.
   - `can_spin_down(current_state: str) -> bool`: True if Onln, UGood, or UBad. False if Rebld or Failed.
   - `can_make_hot_spare(current_state: str, has_existing_dgs: bool) -> bool`: True if UGood and at least one DG exists.

3. New POST endpoints in `web/routes.py`:
   - `POST /drives/{enclosure}:{slot}/mark-ubad` named `drive_mark_ubad`
   - `POST /drives/{enclosure}:{slot}/mark-ugood` named `drive_mark_ugood`
   - `POST /drives/{enclosure}:{slot}/spin-down` named `drive_spin_down`
   - `POST /drives/{enclosure}:{slot}/make-hot-spare` named `drive_make_hot_spare` (request body includes `dg_id: int`)

4. Each endpoint:
   - CSRF + auth required.
   - State machine pre-check: returns 409 Conflict if the action is not allowed in current state.
   - Storcli call.
   - Audit event with appropriate category + summary.
   - Returns 303 redirect to drive detail on success.
   - 502 on storcli error.
   - 500 on audit failure.

Out of scope:
- Frontend (PR-084 templates).
- Foreign config drive operations (separate flow, exists already).
- Bulk drive operations.
- Drive firmware update (out of scope for this PR).

## Implementation notes

State transitions for the drive lifecycle (LSI semantics):
- UGood (Unconfigured Good): drive seen by controller, not in any DG, available for use
- UBad (Unconfigured Bad): drive isolated by controller, ignored for new operations
- Onln (Online): drive is member of a VD/DG, healthy
- Offln (Offline): operator-marked offline (precondition for replace)
- Missing: previously online, now not seen
- Rebld (Rebuilding): rebuild in progress
- Failed: hardware failure detected

The state machine validators ensure operators cannot make invalid transitions (e.g. mark Onln drive as UBad - this would require offline first).

For make-hot-spare: the dedicated-spare assignment requires a target DG. In our setup there's only one DG (DG 0), so the form sends dg_id=0. Future setups with multiple DGs would let operator pick.

Each endpoint pattern mirrors locate/patrol_read structure. Copy, modify storcli command + category + state machine pre-check.

The state machine pre-check happens BEFORE storcli runs. Return 409 with body explaining why the transition is invalid (e.g. "Cannot mark UBad: drive is Online (must be Unconfigured Good first)").

## Risk

Four new mutating endpoints in security perimeter. Risk heading required.

`spindown` is irreversible at the controller level until the next reboot or explicit spinup. Document this in the audit event summary so operators understand impact.

`make hotspare` is reversible (set bad on the spare drive to remove it from the spare pool). Document in audit summary.
