## Короткий формат сообщений — подготовлен, ещё не развёрнут

Пример формата, не текущая авария:

```text
🔴 SERVER: сбой массива, риск потери данных.
Перешли в ChatGPT. Диски не трогай.
26.10 10:57 · №42
```

Не более двух коротких строк и одной диагностической строки, без пустых строк; всего до 160 символов для SERVER и AI-SERVER. 🔴 — критическое событие, 🟠 — подтверждённый перегрев уровня warning. Отказ, отсутствие и офлайн-состояние диска описываются по-разному. По одному сообщению нельзя утверждать потерю данных или всех уровней защиты.

Под текстом — одна URL-кнопка «Инструкция» на этот runbook. Сам адрес в тело сообщения не входит. Текст передаётся без HTML/Markdown-разбора; callbacks и входящих команд бота нет.

Действие владельца: «Перешли в ChatGPT». Для неисправностей массива или диска добавляется «Диски не трогай». Не добавлять объясняющие абзацы, повторные риски, «Что делать», «Детали», логи, серийные номера и коды VD/PD/storcli. Не угадывать отсек, число дисков или температуру по summary. При неизвестных данных — короткий фактический текст без диагноза.

Нейтральный ручной тест после развёртывания этого PR:

```text
🧪 SERVER: тест уведомлений
Действий не требуется.
```

У теста нет события, номера, перехода состояния или диагностического времени. Он не утверждает, что автоматическая доставка проверена. Команда отправляет реальное сообщение; смена chat-id меняет получателя, а не превращает отправку в dry run.

### Подтверждённые ограничения детектора

- Полностью исчезнувшая из успешного snapshot запись диска сама по себе не создаёт Missing-событие: детектор перебирает только текущие диски. Если массив при этом стал Dgrd/OfLn, его событие покрывает проблему. Если VD не изменился или тоже исчез, гарантированного оповещения нет; успешный сбор не создаёт outage. Синтетическое событие Missing этого не проверяет.
- Классификация состояний физических дисков чувствительна к регистру/пробелам. Варианты `failed` и ` Missing ` могут не создать критическое событие. Нормализация текста сообщения это не исправляет.
- При первом снимке нет проверки температуры контроллера; уже высокая и затем неизменная температура может остаться без события до нового подходящего перехода.
- CacheVault считает здоровыми только точные Optimal/Optl. Иные написания могут создать критическое событие; короткий текст при неизвестном состоянии не выдумывает неисправность.

Эти ограничения воспроизведены на моках в PR коротких сообщений и остаются отдельными задачами. Они не доказывают аппаратный сбой на SERVER. Схема, классификация и правила доставки в этом PR не меняются.
